# Voice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** You can talk to any chat on the drive and hear it answer. Phase 1 ships push-to-talk in the composer and spoken replies, on every provider, through the host and an OpenAI key. Later phases add holding ⌘J, a hands-free loop, the phone's voice bar, and (v2) a live voice in front.

**Architecture:** Speech wraps the existing turn (spec, "The two shapes", A). The browser records a clip with `MediaRecorder` and posts it to the host; the host forwards it to OpenAI's transcription endpoint and answers with text; the text is sent as an ordinary turn with `context.spoken: true`, which adds one context line telling the agent its reply will be heard; when the turn ends, an `<audio>` element plays `GET /agent/turns/:id/speech`, which the host streams from OpenAI's speech endpoint after cleaning the reply with `speakable()`. No new dependency: Node 22's `fetch`, `FormData` and `Blob` on the host; `MediaRecorder`, `AnalyserNode` and `<audio>` in the browser.

**Tech Stack:** Node 22 ESM, `node:test`, Playwright browser tests (Chromium's fake media device), OpenAI `gpt-transcribe` and `gpt-4o-mini-tts`.

**Spec:** `docs/superpowers/specs/2026-10-10-voice-design.md`; the drive page **Notes and Sketches/Agents and Chat/Voice**.

## Global Constraints

- No new npm dependencies. Node 22.
- The OpenAI key is the `openai` field of `.agent-keys.local` (the one Codex uses). It is read only on the host, sent only as `Authorization: Bearer` to `config.openaiBase`, and never appears in a response body, a log line or argv.
- Audio is never written to disk: not the drive, not `.marble/`, not a temp file. A clip lives in one request's memory.
- Voice routes live under `/agent/`, so the gate, `sameOrigin` for non-GET, and the ungated-host rules apply unchanged.
- Caps: a clip at most 4 MB and 120 s (`MARBLE_DRIVE_VOICE_MAX_SECONDS`); a spoken reply at most 2,000 characters after `speakable()`.
- Models are settings with defaults, not constants in code: `transcribeModel: 'gpt-transcribe'`, `speechModel: 'gpt-4o-mini-tts'`, `voice: 'marin'`.
- The microphone opens only on a press, closes (every track stopped) when listening ends, and never stays open in a hidden tab.
- Words on screen are the spec's list (Talk, Listening, Writing it down, Send, Cancel, Speaking, Stop, Read aloud, Said aloud) and its error lines. Icons are drawn SVG in currentColor, 20 in a 44 hit box. Nothing moves at rest. Design Don'ts' scan runs on every changed style and string.

## Review Focus

1. The key never reaches the browser, a response, or a log, including the error path when OpenAI answers 401.
2. No audio reaches disk on any path (success, OpenAI down, client abort mid-upload).
3. A phone on iOS Safari: `audio/mp4` clips are accepted, and the first spoken reply plays (the `<audio>` element is unlocked by the press that started listening).
4. A spoken prompt on a running turn is dispatched as Steer, and a spoken turn that asks says so without approving anything.
5. A drive without an OpenAI key draws no microphone, and Read aloud falls back to `speechSynthesis`.

### Task 2: The host's ears and voice

**Files:**
- Create: `server/agent/voice/openai.js`
- Modify: `server/agent/keys.js` (a host-only `value(name)` reader; `flags()` and `asEnv()` unchanged)
- Test: `test/agent-voice-openai.test.js` (a fake OpenAI on a local port, as `agent-setup.test.js` fakes `/v1/models`)

**Interfaces:**
- `createVoice({ keys, baseURL, fetch = globalThis.fetch, settings })` → `{ available(), transcribe({ audio, type, keywords, signal }), speak({ text, voice, instructions, signal }) }`
- `available()` → `{ ok: true } | { ok: false, why: 'no-key' }`
- `transcribe` → `{ text }`. It posts `multipart/form-data` to `{base}/v1/audio/transcriptions` with `file` (a `Blob` of `type`, named `clip.webm` or `clip.m4a`), `model`, and `keywords` (joined as the API wants; check the field shape against the live docs when building and record it in the test). It throws a `VoiceError` with `status` and a person-facing `message`: 401 → "OpenAI didn't accept the key in Settings › Voice."; network or 5xx → "OpenAI didn't answer. Try again."; an empty transcript → "Didn't catch anything. Try again a little closer."
- `speak` → a `Response` whose body is `audio/mpeg`, from `POST {base}/v1/audio/speech` `{ model, voice, input, instructions, response_format: 'mp3' }`. mp3 because every browser streams it in `<audio>`; `wav`/`pcm` are lower latency but need Web Audio plumbing (a later change if the first word is slow).

**Interfaces:**

### Task 5: Listening and playing in the browser

**Files:**
- Create: `runtime/voice.js` (loaded by `injectCarrier` after `agent.js`, before `agent-ui.js`), exporting `globalThis.marbleVoice`
- Modify: `server/app.js` (the script tag)
- Test: `test/agent-voice-quiet.test.js` (the pure parts, loaded the way `test/agent-phone.test.js` loads `agent-phone.js`)

**Interfaces:**
- `marbleVoice.listen({ onLevel, onState }) → { done: Promise<{ blob, type, seconds }>, send(), cancel() }`. `getUserMedia({ audio: { echoCancellation: true, noiseSuppression: true } })`; `MediaRecorder` with the first supported of `audio/webm;codecs=opus`, `audio/mp4`; an `AnalyserNode` for `onLevel(0..1)` at animation-frame rate; ends on `quietEnd()` or `send()`; `cancel()` and `visibilitychange` to hidden discard the clip; every path stops every track.
- `quietEnd(levels, { floorMs = 300, quietMs = 1200, frameMs = 16 }) → boolean`: pure; true once speech rose above a floor measured over the first `floorMs` and has then stayed below it for `quietMs`.
- `marbleVoice.play(url, { onLevel, onEnd }) → { stop() }` and `marbleVoice.stop()`: one `<audio>` element per tab, created and `play()`-ed silently inside the first press so iOS lets later plays through; a second `play` stops the first.
- `marbleVoice.say(text)`: `speechSynthesis` for Read aloud on a drive without a key.
- `marbleVoice.transcribe(clip, { doc }) → Promise<string>`: the POST, keeping the last clip for one retry.
